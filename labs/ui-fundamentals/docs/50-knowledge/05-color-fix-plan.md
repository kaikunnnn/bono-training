# 記事「ダメUIを4段階で直す — 配色の基本」計画（#247）

## 目的

- 動画で使う配色のダメUI（bad-ui/color-bad-ui.html）を、配色記事の基本に沿って4段階で直す流れを、記事で読めるようにする
- 各段階＝配色記事の章1つ（A 役割 / B 量 / D 意味 / C 数値）。その段階で何が変わったかを、直す前と直した後の画面を並べて見せる

## 置き場所

- シリーズの入口URL（UIデザインの基礎シリーズ）に、新しいタブとして足す（連作は1リンク: feedback-series-one-link）
- ファイル: knowledge/color-fix.html → build-series.mjs の SERIES に `{ slug: "colorfix", label: "配色の直し方" }` を足す
- 画像: ダメUIの各段階のスクリーンショット（1280×800、ピンなし）を data URI で埋め込む。段階ごとに、変わった場所の拡大も添える

## 構成

- 導入
  - どんな画面か（タスク管理アプリ、14個の配色のミス）
  - 読み方: 1段階＝配色記事の章1つ。各段階で直すのはその章の項目だけ。配置は全段階で同じ
  - なぜ A→B→D→C の順か（数値の確認を最後に1回だけ行い、同じ所を2回直さないため）
- 段階1〜4（各段階の中身は同じ型）
  - 見出し: 「段階N　章の名前」
  - その章の基本を1〜2文
  - 比較の図: 直す前（前の段階）と直した後（この段階）を並べる＋変わった所の拡大
  - 直した項目ごとに ①何をどう直したか（具体的な値） → ②理由・出典（台帳ID） → ③背景
  - 「まだ残っているミス」
- まとめ
  - ダメUIとアフターの全体比較
  - 配色以外に直したところ（ナビの階層・絞り込みのタブ・ボタンの数など）は短く。配色の記事なので深入りしない

## 書き方のルール

- 主張は台帳（docs/10-ledger/colors.md・nav.md）の ID 付きのものだけ。新しい主張は先に台帳へ
- 断定しない。会社によって割れている所は割れていると書く（例: 選択中の色、優先度の色、通知バッジの色、背景の色み）
- 数値（コントラスト比・彩度）は bad-ui/contrast.py の出力を使う
- 文章はブログ調の段落でつなぐ。「〜ですよね」を使わない。自作の用語を作らない
- 表は使わない（オーナーの閲覧環境）

## 確認

- node knowledge/checks/run-all.mjs が通ること（シリーズのビルドを含む）
- 公開前に、各段階の画像が今のダメUIと一致しているか目で確かめる
