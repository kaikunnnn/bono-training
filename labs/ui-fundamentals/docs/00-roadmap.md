# ステップ型 DailyUI トレーニング — ロードマップ

決定事項(2026-07-03):
- **v1主対象**: BONO会員の初心者(未経験〜学習初期。「作る前」で手が止まる層)
- **リサーチアクセス**: BONO会員への声かけ + SNS/コミュニティ募集の両方が可能
- **初手**: 検証より先にリファレンス台帳と模範(golden sample)を1本作り込む

## 進め方の原則

1. **縦切り1本主義** — 全お題×全ステップを横に広げず、お題1つのSTEP0-4を完全に作りきる。これが品質の基準器になり、プロンプト・台帳・検証ルールの原型がここから生まれる。
2. **コンテンツの質=体験の質** — AIプロダクトの体験はUIより先にコンテンツとプロンプトで決まる。Figmaでの画面デザインは体験が検証されてから。
3. **作ったら人力で演じて検証** — 開発ゼロのオズの魔術師テストで、仕様書を書く前に体験の質と詰まりポイントを確かめる。
4. **各フェーズに「直す/殺す」基準を持つ** — 検証で何が出たら設計を変えるかを事前に書いておく。

## フェーズ

### Phase 0: 仮説マップと成功定義(〜1日)
- 企画が前提にしている仮説を列挙し、リスク×不確実性でランク付け → `01-hypothesis-map.md`
- 成功指標の定義(セッション完走率 / STEP4での言語化の質 / 翌週リピート意向)

### Phase 1: コンテンツの核を1本作り込む(1〜2週)★初手
- お題選定: テイスト依存が低いフォーム系1つ(候補: Sign Up / 設定画面)
- リファレンス台帳: **この1本に必要な分だけ**埋める
  - 引用元候補: Apple HIG(Forms, Text fields) / Material 3 / GOV.UK Design System(フォームの根拠が最も明文化されている) / WCAG 2.2 / NN/g
- STEP0-4の模範版(golden sample)を人力で完全に作りきる
- 品質基準: 全主張に出典 / 初心者が1時間で完走できる分量 / STEP4が「答え合わせ」でなく「比較」になっている

### Phase 2: デスクリサーチ + インタビュー準備(Phase 1と並行)
- DailyUI挫折談の一次情報収集(X / note / Reddit)→ 詰まりポイント分類
- BONO会員向け募集文 + インタビュー/観察セッションのガイド作成

### Phase 3: オズの魔術師テスト(Phase 1完了後、1週)
- golden sampleを台本に、実ユーザー2〜3名へ1セッション。AI役は人力(裏でClaude併用)
- 観測項目: どのSTEPで手が止まるか / 引用は読まれるか・信頼されるか / 1時間で終わるか / STEP4が思考停止コピーに堕ちないか
- 事前に「直す/殺す」基準を明文化してから実施

### Phase 4: 体験設計(1週)
- テスト結果で4ステップ構成を修正
- ストーリーボード / サービスブループリント(ユーザー・AI・リファレンスの3レーン)
- セッション内の感情曲線 + 継続設計(Day 1 → Day 30)

### Phase 5: UIデザイン(1〜2週)
- 情報設計 → ワイヤー → ビジュアル(Figma)。BONOのトンマナに合わせる

### Phase 6: プロトタイプ + 検証 → 開発仕様書
- 台帳RAG + プロンプトで動くプロトタイプ → 5名テスト(完走率・理解度)
- 仕様書4ブロック(台帳 / お題→型対応表 / ステップ生成ロジック / 検証ルール)を確定
