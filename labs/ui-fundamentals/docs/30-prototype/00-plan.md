## 1. 目的 — 何を確かめるためのプロトタイプか

**「この学習体験は成立しているか」をTakumi自身の身体で判断する。** 見た目のデモでも技術検証でもなく、体験の質の検証が主目的。

判断したい問い(仮説マップH1〜H6のセルフ検証版):
1. 「問う→考えさせる→型」のテンポは気持ちいいか、まどろっこしいか
2. 引用(根拠: P-02等)は信頼として届くか、ノイズか。**どの表示濃度が正解か**
3. 選択課題(ラベルの型・CTA文言)は「自分で決めた」手応えを生むか
4. STEP4の3点比較(自分/模範/実物)は答え合わせに堕ちないか
5. 60分は本当に持つか。どのステップで飽きるか

## 2. スコープ

### v0(台本駆動)に入れるもの
- お題01「Sign Up」のSTEP0〜4全フロー(台本v2を組み込み)
- ガイドとの対話UI(回答入力・選択課題・「考えてから型が出る」順序の再現)
- 引用の表示(**3案を切替可能にして比較検証する** — これがv0の最重要機能)
- STEP3: 数値の約束+チェックリスト(Figma作業は実物のFigmaで並走)
- STEP4: 実物(Airbnb)・模範(v3)画像との3点比較
- セッションログの書き出し(回答・選択・所要時間 → 観察シートに転記できる形)

### v0に入れないもの(理由付き)
- 生成AI応答 → v1で。体験の骨格が固まる前に生成を入れると、体験の問題かAIの問題か切り分けられない
- 複数お題・アカウント・進捗保存 → 検証に不要
- 決定論チェックの自動計算(Figmaデータ検査)→ 本番の目玉だが、v0ではチェックリストの手動確認で体験だけ再現
- 課金・BONO連携 → 検証に不要

### v1(本AI)で足すもの
- Claude API接続。**システムプロンプト=台帳4層+台本の設計原則**、台帳にない主張の出典ガード(応答内の引用IDを機械検証し、台帳外の断定を弾く)
- 学習者の自由入力への応答(v0では定型のみ)

## 3. 工程(3段階・各工程に完了条件)

### 工程A: 体験フロー+ワイヤー(まずここ)

成果物: 画面フロー図+lo-fiワイヤー(Figma)

設計する論点:
- **A-1. 対話の器**: チャット型(メッセージが流れる)か、ステップカード型(1画面1問で置き換わる)か、ハイブリッドか。※教材自身の方法論を自己適用し、**実在する学習/AI対話UIの実物**(Duolingo・ChatGPT/Claude・Notion AI等)を集めてから決める
- **A-2. 引用の表示濃度3案**: ①インライン全表示 ②折りたたみチップ(タップで原文+URL) ③末尾まとめ。→ v0で切替比較
- **A-3. Figma並走の画面設計**: STEP3中はユーザーはFigmaで作業する。プロトタイプ画面は「横に置いて邪魔しない」状態(コンパクト表示/チェックリスト常駐)をどう作るか
- **A-4. 進捗と時間の見せ方**: 5ステップの現在地、残り時間の圧を掛けすぎない表示

完了条件: 5ステップ全部が画面遷移として表現され、A-1〜A-4に設計判断(根拠付き)が付いている

### 工程B: プロトタイプUIのFigmaデザイン

成果物: ミニトークン定義+主要3画面(①セッション対話画面 ②STEP3作業中画面 ③STEP4比較画面)のhi-fi

- プロトタイプ自体のUIにも4層リファレンス方式を適用(実物→トークン→ルール検査)。トーンはBONOに寄せる(Takumiの判断領域)
- 完了条件: Takumiレビュー通過

### 工程C: 実装

- **v0**: 静的Webアプリ(1ファイルHTML or Vite)。台本v2を対話スクリプトとして組み込み。ローカルで開くだけで動く
- 完了条件: Takumiが60分セッションを通しで体験できる
- **セルフテスト**: 観察シートを自分に適用して記録 → 直すリスト → 台本・体験・UIに反映
- **v1**: Claude API+出典ガード。完了条件: 台帳にない主張を含む応答が機械的に検出・遮断されること

## 5. リスクと先回り

- **台本の文章量**: 紙の台本は対話UIでは長すぎる可能性大 → 工程Aで「1メッセージ=3文以内」等の分割ルールを決め、台本を対話用に再編集する
- **自己検証のバイアス**(作者は体験を好意的に見る)→ 観察シートで事実記録+後日の実ユーザーテストで補正。v0で「知らないお題」を1つ自分に課すのも有効(お題02を仮生成して初見体験する)
- **チャット型の既視感**: ただのChatGPTに見えると価値が伝わらない → A-1で実物リファレンスを集めた上で、ステップ構造・引用・比較という固有要素が画面上で主役になる器を選ぶ
