## 2. 通し歩行テスト(パターン2をミナとして)

各画面で ⭕️=通る / ⚠️=つまずき の判定と根拠。

| 場面 | 判定 | ミナの体験 |
|---|---|---|
| オリエンテーション | ⭕️ | 3コマで流れが分かる。「うまく作れなくても大丈夫」が効く |
| ブリーフ: シナリオ・載せるもの | ⭕️ | 8個のリストで「作るもの」が具体化する |
| ブリーフ: できたかチェック11項目 | ⚠️ | **「44pt」「4.5:1」の意味をまだ知らない。**意味不明な項目が11個並ぶと「難しそう」と不安になる |
| よむ: 分量と時間 | ⚠️ | 「約10分」と言われたが、基本7つ+実物探検で**実際は15〜20分**。約束とズレると信頼が下がる |
| よむ: 引用カード | ⚠️ | **必読の引用文が英語。**読めない。「必読なのに読めない」で自信を失う |
| よむ: GOV.UKの登場 | ⚠️ | 「英国政府?私はアプリを作りたいのに」— なぜこれがお手本なのか一言もない |
| よむ: フィールドワーク | ⚠️ | Airbnbを開くと電話番号の入力欄。「**入力しちゃって大丈夫?**」と個人情報の不安で手が止まる |
| よむ: ライブ実例(iframe) | ⚠️(小) | 中身が英語のフォーム。「英語だけど、形を見ればOK」の一言がない |
| つくる: はじめの一歩 | ⭕️ | フレーム作成から書いてあるので入れる |
| つくる: 単位 | ⚠️ | 「44pt」と「48px」が混在。**Figmaにptは無い**ので「どっちで作るの?」と詰まる |
| つくる: Figma操作の詰まり | ⚠️ | ヒントは設計判断のみ。オートレイアウトで格闘し始めたら誰も止めてくれない |
| みくらべる: 3枚並び | ⭕️ | 「ちがい=まちがいではない」の先回りが効く |
| みくらべる: 観点の自己判定 | ⚠️ | 「できた/直したい」を選べと言われても、**できたかどうかの見分け方が分からない** |
| ひとこと・完了 | ⭕️ | 例文があるので書ける。祝福で終われる |

## 3. 改善リスト(優先度付き)

### P0 — このループで直す(理解・信頼を直接壊すもの)
1. **引用の日本語訳**: 必読引用の英語原文に日本語訳を併記(原文は消さない=嘘のなさ維持)
2. **単位の統一**: 表記をFigma基準のpxに統一し、「Appleのルールでは44pt。Figmaでは44pxと同じでOK」の単位メモを1箇所に
3. **時間の正直化**: 「よむ」は「読むだけで10分・実物探検こみで15分」。オリエンテーションの時間表記も更新
4. **ブリーフのチェック11項目に前置き**: 「知らない言葉があっても大丈夫。ぜんぶこのあとの『よむ』で学びます。いまは眺めるだけでOK」
5. **フィールドワークの個人情報不安の先回り**: 「何も入力しなくてOK。見るだけで、登録もされません」

### P1 — このループで直す(体験の質を上げるもの)
6. **GOV.UKの一言紹介**(初出時): 「英国政府が公開しているデザインのルールブック。誰でも読めて、根拠がいちばん細かい」
7. **Figma操作の逃げ道**: はじめの一歩に「オートレイアウトは使わなくてOK。四角(R)とテキスト(T)だけで作れます」
8. **観点の見分け方**: みくらべるの4観点に「確かめ方」を付ける(例: 目立ち方→「画面から1歩はなれて見て、最初に目に入るのがメインボタンならOK」)
9. **ライブ実例への一言**: 「英語のフォームですが、読めなくてOK。形と動きを見てください」
10. **チェックとスタイルの接続**: 「キットの5色を使っていれば、色のコントラストは確認済み(自動的にクリア)」

### P2 — 保留(次ループ以降・理由付き)
11. スマホ連携(QRでフィールドワークURLをスマホへ)— 実装コストの割に検証価値が低い、実ユーザーテスト後に
12. 「なぜこの判断か」リストのデフォルト展開 — 情報量とのトレードオフ、実ユーザーの行動を見てから
13. 完了後の継続導線(ストリーク等)— G7として記録済み、プロトタイプの目的外
14. 音声・アニメーション等のリッチな祝福 — 過剰投資

# 検査レンズの拡張(2026-07-08・第2ループから適用)

ペルソナ歩行に加え、以下の6レンズで検査する。①②は**機械計測**(感想でなく数値):

| レンズ | 方法 | 基準 |
|---|---|---|
| ① 文章 | スクリプトで全文の文長を計測 | 1文40字目安・55字超は分割候補。用語の初出説明 |
| ② 見出し | 見出しだけを抽出して並べる | 見出しだけ読んで話の流れが分かるか(スキャン可能性) |
| ③ 構成 | カードの順序・1カード1トピック・橋の一言 | 考え方→実物→方針→部品→まとめ の論理順。発展は明示 |
| ④ 表現デザイン | 行長・強調の密度・情報の階層・訳と原文の主従 | 行長40字前後・太字の渋滞なし・初心者には訳が主 |
| ⑤ ユーザーフロー | 遷移図・中断/再開・行き止まり | リロード復帰・全画面から戻れる・状態が消えない |
| ⑥ 自己適用 | 教材自身が教えている原則を守っているか | 教材UIのトークン一貫性(記録し、矛盾は直すか理由を書く) |
