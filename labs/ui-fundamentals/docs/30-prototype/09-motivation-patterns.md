# 第3ループ: 「やりたい!」の入口設計 — 進め方と体験アイデア

- 2026-07-08。テーマ: ユーザーが**理解して「このお題をやりたい!」と思える**入口(ホーム/ブリーフ)を作る

## 1. テストで分かっていること(このループの入力)

- ミナの動機: 転職・ポートフォリオ(D-05: 提出が自動で作品集になる設計が実在)/ 不安: 「時間を無駄にしたくない」「センスがないかも」
- DailyUI挫折の原因: 完成までの道が見えない・やる意味が見えない
- 現状パターン4の入口: お題カード(タグ+説明文)→ブリーフ。**「何をするか」は分かるが、「やった先に何が待つか」が見えない**。やる気の根拠が文字だけ
- 使える実在の知見: FMは完成イメージを先に見せる(D-01)/ Refactoring UIはbefore→afterで「学べば直せる」を見せる(D-09/原則-08)/ Duolingoは達成単位を小さく約束(体験-05)/ 祝福・進歩の可視化が残存率を動かす(実測A/B)

## 2. 体験アイデア(6案)と選定

| # | アイデア | ミナへの効き筋 | 判定 |
|---|---|---|---|
| A | **ビフォー→アフター**: よくある初心者の画面 vs 実在アプリの画面を並べ、「差は決めごとを知っているかだけ」 | 「センスがないかも」不安の反転。学べば直せる、が一目で分かる(Refactoring UI型) | ✅ 作る(5A) |
| B | **60分後のあなた**: 完成形を**ぼかして**予告+身につくスキル+ポートフォリオになる、を宣言 | 時間投資の回収が見える。ネタバレ(模範の早見せ=コピー化)はぼかしで回避 | ✅ 作る(5B) |
| C | **間違い探しフック**: ダメな画面を見せ「プロが直したい所が7つ。いくつ見えますか?」→「60分後にはぜんぶ見えます」 | 好奇心で引き込む+「見える目」が成果だと予告(Uxcelのクイズ的入口) | ✅ 作る(5C) |
| D | 実務接続の宣言(「SpotifyやUberのデザイナーと同じ仕事」) | 転職動機に直結 | 5A〜Cに1行で内蔵(単独パターン不要) |
| E | ナビの招待の強化 | 温度は既にある | 既存で十分 |
| F | ストリーク/連続記録 | 継続には効くが「初回のやりたい」には効かない | 見送り(G7・製品化時) |

### 制約(方法論との整合)
- **模範の早見せはしない**(思考停止コピー防止の原則)。「アフター」には模範ではなく**実物(Airbnb)の引用**を使い、5Bのぼかしで完成形の存在だけ予告する
- ダメな例は**自作**する(実在サービスを「ダメな例」として晒さない — 批評の倫理)

## 3. 実装計画

1. **「ダメな例」をFigmaで自作**(消えるうす文字ラベル・色3色・ボタン不揃い・ログイン案内なし・余白バラバラ — チェックリストの違反を7つ仕込む)→ 書き出し
2. パターン4を複製して**5A/5B/5Cの3変種**を作成(変えるのはホームのお題カード+ブリーフ冒頭のフックのみ。よむ以降は共通=変数を分離して比較可能に)
3. **同じミナ+6レンズで3変種をテスト**し、入口の「理解→やりたい」への効き・不安の発生を比較 → 推奨を出す

## 4. テスト結果(ミナ+6レンズ、入口に焦点)

### 5A ビフォー→アフター
- **理解** ⭕️: 左の画面を見た瞬間「これ、私が作るやつだ…」と自分ごと化。差の正体=決めごと、が一目
- **やりたい** ⭕️強: 「センスの差ではありません」が、ミナ最大の不安(センスないかも)を正面から反転する
- ⚠️: 右(Airbnb)は電話番号UIで今日作るメール式と細部が違う / 左に自分を重ねて凹む人がいる可能性は「がんばって作ってもこうなりがち」の書き方で中和済み

### 5B 60分後のあなた
- **理解** ⭕️: 得られるもの(スキル+ポートフォリオ)が明確。転職動機に直結
- **やりたい** ○: 悪くないが、動機の根拠が言葉寄りで5Aほど体感的でない
- ⚠️: ぼかし画像は情報ゼロで「見せてくれないの?」のフラストレーション余地 / スキルタグは学ぶ前の用語なので訴求が弱い

### 5C 間違い探し
- **理解** ⭕️: 「7つある、いくつ見える?」— ルールが一瞬で分かる
- **やりたい** ⭕️強: 好奇心+「見える目が今日の持ち帰り」という成果の再定義。**完了画面の再挑戦(もう一度見る→今度は7つ見える)は、成長の実感を最も直接に演出できる**(Duolingoの「進歩を見せる」と同型)
- ⚠️: 0個の不安は「0個でも問題ありません」でケア済み / 「7つ」とチェック11項目の数の関係は将来整理

### 比較結論と推奨
- 「やりたい」の強さ: **5C ≧ 5A > 5B**。不安の反転は5Aが最強、成長実感のペイオフは5Cが独走
- **5Aと5Cは排他ではない**: 入口=5A(ビフォーアフターで納得)+完了=5C(再挑戦で成長実感)の統合形が本命候補。5Bのポートフォリオ1行はどこにでも足せる
- 次ループ: Takが3変種を体験して感触を選ぶ → 統合形 or 実ユーザーテストへ
