## 判定

### G1 通し体験 — ⚠️ 条件付き合格
- ブリーフ→学習7ステップ→制作→比較→言語化の全フローを実装。回答ゲート(答えるまで進めない)・比較の最低1問・言語化必須も実装済み
- JS構文チェック・必須要素IDチェックは機械検証済み
- **未検証**: 実ブラウザでのクリック通し(Chrome拡張未接続のため)。Takが `prototype/index.html` を開けば即確認可能。ここは正直に「未検証」と記録する

### G2 嘘のなさの可視化 — ⚠️ 概ね合格・注記2点
- 学習コンテンツの主張には引用チップ(計19種)が付き、タップで原文引用+原典URL(新タブ)に到達できる。引用文はすべて台帳からの転記
- 注記1: Q-09(Baseボタン)は原文verbatimでなく「コード値の要約」。台帳と同じ「計算値」注記の扱い
- 注記2: V-06 / V-obs は実測観察の要約であり原文引用ではない(観察ソースの性質上妥当だが、表示上「引用」と「観察」の区別が画面に無い)

### G3 学習ループ5局面 — ✅ 合格
- ①キット(s2: シナリオ/完成条件先出し/部品/提出のかたち)②マイクロステップ(s3: 7本、説明→チップ→問い→型の順を固定)③制作支援(s4: チェックリスト常駐+3段ヒント+経過時間)④比較(s5: 3点並置+観点別+再比較ループ)⑤言語化(s6: 必須+セッション記録の書き出し)— 全局面あり

### G4 体験設計A-1〜A-8の反映 — ⚠️ 2つ不完全
- A-1レッスン型 ✓ / A-3キット ✓ / A-4先出し ✓ / A-5マイクロステップ ✓ / A-6ヒント3段 ✓ / A-7比較+再比較 ✓ / A-8言語化 ✓

### G5 判断材料の密度(Takの目的への適合)— ❌ ここが最重要弱点
- Takのビジョンの中心は「**カードならカードの定義・挙動・使用サービスをDSから学び、それをお題で出力する**」= パターン辞典的なインプット
- 現状の学習ステップは「問い駆動」に寄っていて、パターンそのものの教育(定義/挙動/どのサービスで使われるか/DSごとの定義差)が選択課題の付属物になっている
- 「AIがDSを参照してどこまでのステップ設計ができるか見たい」という目的に対し、**パターン教育の密度の選択肢を見せられていない**

## 結論 → P6の対象

**最重要弱点 = G5(パターン教育の密度と形式)。** 改善パターンを3つ、プロトタイプ内で切替可能にして実装する:

| 案 | 名称 | 設計 |
|---|---|---|
| A | 問い駆動型(現状) | 説明2〜4文+チップ+問い。テンポ最速・інプット最小 |
| B | パターンカード型 | 各ステップに「パターン辞典カード」(定義=DS引用 / 基本挙動 / 使われているサービス)を差し込む。Takのビジョンに最も近い |

+ G4の不完全2点(末尾出典まとめ / s5の11項目判定)は改善パターンではなく単純修正としてP6内で直す。
