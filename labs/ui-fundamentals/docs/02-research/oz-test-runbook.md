# オズの魔術師テスト — 実施手順書(Runbook)

- **目的**: 開発ゼロで教材体験の質を検証する。台本(`20-golden-sample/signup-session.md`)のAI役をTakumiが人力で演じ、実ユーザー2〜3名に60分セッションを提供する
- **検証対象**: 仮説マップ(`01-hypothesis-map.md`)のH1〜H6
- **形式**: 1対1・オンライン(Zoom等)・60分+事後インタビュー15分

---

## 1. 事前準備チェックリスト

- [ ] 参加者2〜3名の確定(募集文: `recruiting.md`)。条件: デザイン学習6ヶ月以内目安、Figma基本操作可
- [ ] 画面録画の同意を事前に取得(募集文に明記済みの旨を口頭でも確認)
- [ ] 参加者に空のFigmaファイルを作ってもらい、共有リンクを事前受領(当日の環境トラブル回避)
- [ ] AI役の送信手段を決める: Zoomチャット or Discord DM。**台本のAI発話をコピペで送る**(音読より「AIとのチャット」の再現度が高い)
- [ ] 台本を手元に開く+裏でClaudeを開いておく(台本外の質問が来た時の回答生成用 — ただし下記の鉄則に従う)
- [ ] 観察シート(`oz-observation-sheet.md`)を参加者分コピー
- [ ] タイマー(STEP別の時間計測)

## 2. ウィザード(AI役)の鉄則

1. **台本のAI発話はそのまま送る**。アドリブで盛らない
2. **台本にない質問が来たら**: 台帳(`10-ledger/`)にある根拠だけで答える。台帳にないことを聞かれたら「それは今日の教材の範囲外です」と正直に返す — **これは本番AIの「出典なしの主張を弾く」ガードのシミュレーション**。ここで我慢できないと検証にならない
3. **教えたくなっても問いを先に**: 台本の「問う→考えさせる→型」の順を崩さない
4. **沈黙は7秒待つ**: 詰まりこそ観測対象。すぐ助けたら詰まりポイントが見えない
5. 実物スクリーンショット(Airbnb)は**STEP4まで絶対に見せない**

## 3. セッション進行(75分)

| 時間 | 内容 |
|---|---|
| 0:00〜0:05 | 挨拶・趣旨説明(「新教材のテスト。あなたではなく教材を試す。詰まったらそれが最高のデータ」)・録画開始 |
| 0:05〜0:10 | **STEP0** お題提示・3つの問い |
| 0:10〜0:20 | **STEP1** 要素の洗い出し→削る→グルーピング |
| 0:20〜0:30 | **STEP2** パターン選択(2-1ラベル / 2-3 CTA文言の「選択」を必ず通す) |
| 0:30〜0:55 | **STEP3** Figma制作(ウィザードは沈黙。質問が来た時だけ台本の返しパターンで応答) |
| 0:55〜1:05 | **STEP4** 3点比較(実物開示はここ)・学びの1文 |
| 1:05〜1:15 | 事後インタビュー(観察シート後半の質問) |

時間が押したら: STEP3を5分延長してSTEP4を圧縮するのは**不可**(STEP4がこの教材の核)。STEP3を打ち切って「未完成のまま比較」に進む。未完成でも比較は成立するかも観測対象。

## 4. 「直す/殺す」の事前基準

テスト後の感想戦で動かさないよう、**先に**決めておく:

| 観測結果(3名中) | 判断 |
|---|---|
| 2名以上がSTEP4で「模範に合わせて直したい」だけを言う(自分の判断を守る場面ゼロ) | STEP4の比較設計を作り直す(H5棄却) |
| 2名以上が引用(根拠: ◯◯)を「読み飛ばした/邪魔」と回答 | 引用の表示濃度を再設計(H2要修正)。教材の核なので**3名全員なら企画レベルで再考** |
| 2名以上がSTEP1〜2で「早く作らせて」と退屈を示す | STEP1〜2を圧縮・制作と並行型に再設計(H1要修正) |
| 2名以上がSTEP3でFigma操作自体に15分以上詰まる | 対象者定義かFigmaテンプレート提供を再設計(H4棄却) |
| 完走が3名中1名以下 | 60分・5ステップの枠組み自体を再設計(H3棄却) |

## 5. 記録

- 録画+観察シート(セッション中はシートに時刻と発話メモだけ。分析は録画で後から)
- セッション直後に15分で「一番強かった瞬間・一番まずかった瞬間」を各1つメモ(鮮度が命)
- 3名分終了後、観察シートを横並びにして仮説H1〜H6ごとに判定 → `oz-results.md` にまとめる(テスト後に作成)
