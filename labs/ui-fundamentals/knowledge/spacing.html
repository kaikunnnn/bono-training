UIの余白で
知るべき9個

余白は「なんとなく空ける」ものではありません。8pxグリッドから近接・タッチターゲット・行送り・レスポンシブ余白まで、余白を「数値と根拠」で語れるようになる9個を、一次ソースに紐づけて解説します。

読了目安 約10分（日本語の読速 約400〜600字/分を前提）／出典はすべて台帳ID付き

この記事を読み終えるころには、世の中のUIの余白が「見える目」に変わっているはずです。感覚で決めていた余白を、「グループ内より、グループ間を広く」「本文の行間は1.5倍以上」のように、根拠のある初期値で語れるようになります。

大事なのは、断定を鵜呑みにしないことです。「8の倍数が絶対」のような素朴なルールには、実在するデザインシステムの中に反例があります。だからこの記事では、一次ソースが実際に書いていること(事実)と、それを実務でどう使うか(解釈)を、色を分けて示します。

事実＝WCAGやMaterialなど一次ソースの記述を、原文に忠実に言い換えたもの。末尾に出典チップ(台帳ID+URL)が付きます。
解釈＝その事実を、初心者が実務でどう使えばよいかに落とした推奨。断定は避け「原則」「定番」で示します。

01

余白は"機能"である

Material 3 は「レイアウトは画面上の全要素を組織化し、階層を示し、キーアクションに注意を引くために使う」と定義しています。また NN/g は「インターフェースに足す余分な情報の1単位ごとに、重要な情報の相対的な視認性が下がる」と述べています。 S-12 · Material 3 S-07 · NN/g だから余白は「何もない場所」ではなく、整理する・階層を示す・注意を導く、という仕事をしている"機能"です。詰めれば詰めるほど情報が伝わるわけではありません。まず「この余白は何の仕事をしているか」を言えるようにするのが第一歩です。

初心者がやりがちなのは、空いた場所を「もったいない」と感じて要素で埋めてしまうことです。けれど画面は、余白があるからこそ「どれが見出しで、どれが本文で、どこを押せばいいか」が一目で分かります。余白は削るコストではなく、伝わりやすさを生む投資だと考え方を切り替えましょう。

02

8pxグリッド(基本の物差し)

Android の公式ガイドは「Android の UI はレイアウト・コンポーネント・スペーシングに 8dp グリッドを使う」「アイコンなどの小さな要素は 4dp グリッドに揃えるとよい」としています。Material 3 のスペーシングトークンも「スペーシング単位は 8dp スケールに従う(space100 = 8dp)」と明記しています。 F-09 · Android Developers S-15 · Material 3 余白の値に迷ったら、まず 8 の倍数(8 / 16 / 24 / 32 …)から選ぶのが定番です。値の選択肢が絞られるので全体のリズムが揃い、実装への指定もシンプルになります。小さなアイコンまわりだけは 4 の倍数まで許容、と覚えておきましょう。

「8px」を物差しとして持つと、余白を1pxや3pxずつ微調整して迷子になることがなくなります。デザインは「正解の値を当てる」より「使う値の候補を減らす」ほうが速く安定します。8pxグリッドは、その候補を減らすための最初の道具です。

03

近接：距離が"仲間"を伝える

ゲシュタルトの近接の原則では「近くにあるアイテム同士は、同じグループ——似た機能や特徴を共有するもの——として知覚されやすい」とされます。NN/g もフォームについて「ラベルは対応する入力欄の近くに置き、関連するフィールドをグループ化せよ」としています。 S-02 · NN/g S-10 · Laws of UX S-16 · NN/g 実務ルールはシンプルで「グループ内の余白 < グループ間の余白」。線や枠を引く前に、まず余白の差だけでまとまりを作れないか考えます。距離そのものが「これは仲間」という情報を運んでくれます。

たとえばラベルと入力欄はセットなので近づけ、別々の質問の間はぐっと離す。たったこれだけで、罫線を1本も引かずに「どこからどこまでが一つの項目か」が伝わります。逆に、間隔が全部同じだと、どれが仲間なのか読み手が判断できません。

04

フォームの余白の実値

実在プロダクトのデザインシステム Uber Base の実測値では、フォーム項目全体の下マージンは 16px、ラベルと入力欄の間隔は 8px と定義されています。入力欄(default サイズ)の内側パディングは上下10px・左右14pxです。 Q-08 · Uber Base Q-07 · Uber Base これはまさに「グループ内8px < グループ間16px」の実例です。初心者は、この実測値をそのまま初期値として使ってかまいません。自分でゼロから数字を発明するより、実在DSの値を借りるほうが速く、外しません。

数字を暗記する必要はありません。大事なのは「ラベルと欄はセット(=近い8px)」「項目と項目は別(=遠い16px)」という関係です。この関係さえ守れば、値が多少違っても読みやすいフォームになります。まずは 8 と 16、この2つの数から始めましょう。

05

タッチターゲットと"押せる余白"

押せる領域のサイズ基準は3つあります。WCAG は 24×24 CSSピクセル以上(間隔の例外あり)、Apple HIG はデフォルト 44×44pt(周囲に約12/24ptのパディング推奨)、Material / Android は 48×48dp 以上・ターゲット間 8dp 以上、としています。 F-04 · WCAG 2.2 F-05 · Apple HIG F-06 · Google / Material 24px は「規格上の最低ライン」、44pt / 48dp が「快適さの基準」と捉えるとよいです。モバイルでは 48dp を既定にし、アイコンの見た目が小さくても、周囲に透明な"押せる余白"(ヒット領域)を足して確保するのが定番です。

ここでの余白は、目に見えない余白です。16pxのアイコンでも、その外側に見えないタップ領域を広げれば48dpを満たせます。見た目の大きさと、押せる大きさは別物——この感覚を持つと、小さなアイコンボタンの押しにくさをちゃんと直せるようになります。

06

行送り(文字の中の余白)

WCAG 1.4.12(Text Spacing)が要求しているのは「ユーザーが行の高さをフォントサイズの1.5倍(段落後2倍・字間0.12倍・語間0.16倍)まで広げても、内容や機能が失われないこと」です。これは著者に1.5倍を強制する基準ではありません。一方 Material 3 の本文トークン body-large は 16px / 行送り24px = ちょうど1.5倍で、Uber Base の実測行送りも同様です。 F-11 · WCAG 2.2 F-08 · Material 3 Q-02 · Uber Base つまり「本文の行間1.5倍」は規格が命じる数字ではなく、堅牢性の基準と実在DSの実値から導かれる"安全な初期値"です。だから本文は行間1.5倍以上を初期値に。ここは「規格の数字を、根拠ごと理解する」練習台でもあります。

行間は「文字の中にある余白」です。詰まった行送りは、行を目で追うときに隣の行と混ざり、読む速度を落とします。和文はとくに、欧文より少し広め(1.7〜1.8倍)にすると読みやすくなります。この記事の本文自体、行間を広めに取っているので見比べてみてください。

07

画面のマージンと密度

Material の画面左右マージンは、モバイル/タブレットで16dp、タブレット/デスクトップで24dpです。また Material 3 は余白の道具を3種類に分けます——パディング(要素の内側)、ギャップ(要素と要素の間)、マージン(それ以上)——そして「コンポーネントでマージンはめったに使わない。まずパディングとギャップで組む」としています。 F-10 · Material S-15 · Material 3 まず画面端にコンテンツを貼り付けないこと(モバイルは左右16dpから)。そして余白を設計するとき「これは要素の内側(パディング)か、要素の間(ギャップ)か」を区別して言葉にすると、レイアウトが崩れにくくなります。

「なんか窮屈」と感じる画面の多くは、画面端の余白が足りていません。逆に大画面で余白を増やさないと、文章が横に間延びして読みにくくなります。余白を「内側/間/外側」の3種で捉えると、どこを足せばいいかを迷わず指させるようになります。

08

レスポンシブな余白

GOV.UK デザインシステムのスペーシングは、画面幅640px(タブレットのブレークポイント)を境に、同じ"単位"でも実際の値が変わるレスポンシブスケールです。たとえば Unit 4 は小画面15px / 大画面20px、Unit 9 は小画面40px / 大画面60px、といった具合です。 F-12 · GOV.UK F-10 · Material 余白は「1つの固定値」ではなく「画面幅に応じて段階的に変えるスケール」として設計するのが定番です。大画面ほど余白を増やすと、要素が窮屈にならず、視線の移動も落ち着きます。このページ自身も、広い画面では左右の余白が広がるようにしています。

スマホで気持ちよかった余白が、そのままだとPCではスカスカ・逆に詰まって見えることがあります。だから「同じ意味の余白でも、画面が広ければ少し大きく」という発想を持ちます。値を1つ決めて終わりにせず、2段階(小/大)で考えるだけでも、見え方は大きく安定します。

09

「8の倍数が絶対」ではない(反例と方針比較)

実在のデザインシステムには、8の倍数でないスケールが複数あります。Uber Base のスペーシングは2px刻みで、10px や 14px を含みます。GOV.UK は5px刻み(0 / 5 / 10 / 15 / 20 / 25 / 30 / 40 / 50 / 60px)です。 Q-06 · Uber Base F-12 · GOV.UK
反例

だから「8の倍数が絶対」は誤りです。Uber Base(2px刻み)も GOV.UK(5px刻み)も、8の倍数だけには従っていません。本質は倍数そのものではなく「宣言したスケール上の値だけを使い、恣意的な値を発明しないこと」。サービスによって刻み幅の方針は異なります。

ここが、事実と解釈を分ける練習の総仕上げです。「8pxグリッド」は強力な出発点ですが、唯一の正解ではありません。大事なのは"自分のスケールを一つ決めて、その中の値だけを使う"こと。8でも、5でも、2刻みでも、決めて守れば品質は保てます。

初心者ほど「絶対のルール」を求めがちですが、実物のDSを覗くと「文脈で正解が変わる」ことが分かります。ルールを覚えるより、「なぜそのスケールなのか」を観察できる目のほうが長く役立ちます。8を疑えるようになったら、あなたの余白の解像度はもう一段上がっています。

まとめ：余白は根拠で語れる

  • 余白は"機能"。整理・階層・注意という仕事をしている(項目1)。
  • 迷ったら8の倍数から。ただし絶対ではなく「決めたスケールを守る」のが本質(項目2・9)。
  • グループ内 < グループ間。距離が"仲間"を伝える(項目3・4)。
  • 押せる大きさは48dpを既定に。見えない"押せる余白"で確保(項目5)。
  • 本文の行間は1.5倍以上を初期値に。和文は1.7〜1.8倍(項目6)。
  • 画面端に貼り付けず、余白は画面幅で段階的に変える(項目7・8)。
