# SEO・見出しタグ規約

新規ページ・コンポーネントを実装する際は、必ず正しい見出し階層（`h1`〜`h6`）でマークアップする。`<p>` や `<span>` に見た目だけ大きい文字を当てて済ませない。

## 基本ルール

- **1ページに `h1` は1つだけ**。ページの主見出し（トップページなら Hero の見出し、記事なら記事タイトル）に使う
- 各セクションの見出しは `h2`
- セクション内のサブ見出し（グループ見出し等）は `h3`
- カードタイトルなど、さらに一段深い要素は `h4`
- **レベルを飛ばさない**（`h2` の次にいきなり `h4` を使わない）。ネストが1段なら `h3`、2段なら `h4`
- 見た目のフォントサイズと見出しレベルは無関係。`text-xs` でも意味的に見出しなら `<h4>` を使ってよい（サイズはCSSで決める、タグは文書構造で決める）

## 判断基準

- そのテキストは「これは何についてのブロックか」を要約しているか？ → 見出し
- ナビゲーションのラベルやボタン文言、リンクの装飾テキストなど、文書構造上の見出しではないもの → `<p>` や `<span>` のままでよい（例: サイドバーのメニュー項目、バッジ文言）

## 実装時のチェック

コンポーネントを書いたら、そのページ全体で見出しタグが以下を満たすか確認する:

```bash
# レンダリング結果からh1〜h6を抽出して階層を目視確認する
curl -s http://localhost:3001/対象パス -o /tmp/page.html
python3 -c "
import re
html = open('/tmp/page.html').read()
for tag, content in re.findall(r'<(h[1-6])[^>]*>(.*?)</\1>', html, re.S):
    text = re.sub(r'<[^>]+>', '', content).strip()[:50]
    print(tag, '|', text)
"
```

- `h1` が1つだけか
- レベルが飛んでいないか（`h2`→`h4`のような欠番がないか）
- 共有コンポーネント（例: `LessonCard` のような複数箇所で使われるカード）は、使われる文脈によって適切な見出しレベルが変わりうる。呼び出し側のネスト位置を確認してから決める

## 既存の共有コンポーネントを拡張するとき

本番の共有コンポーネント（`src/components/lessons/LessonCard.tsx` 等）に新しい表示バリアントを追加する場合、既存バリアントの見出しタグ・DOM構造は変更しない（他ページへの影響を避ける）。新しいバリアントの分岐内でのみ正しい見出しタグを使う。
