# タスク進行の標準ループ

## 順序（必ずこの順で）

**リサーチ → 計画 → 実装 → テスト → 改善**

- リサーチは**現状実装（Explore）・デザイン（Figma）・一般的なベストプラクティス（外部）の3点**を行う。どれか欠けたまま計画を立てない
- ★**外部ベストプラクティスのリサーチは厳守**: 技術選定・アーキテクチャ・パフォーマンス・キャッシュ/データ取得・外部サービス連携（Sanity/Supabase/Stripe/Next.js等）など「業界の定石があるはずの判断」では、**公式ドキュメント等で一般的なやり方を必ず先に調べてから**計画を立てる。自己流・思いつきで実装計画を作らない

## ベストプラクティス駆動の実装（型）

外部リサーチで得たベストプラクティスは、次の型で扱う:

1. **記録・保存**: 採用する定石を**出典URL付き**で rebono/issues の該当MDに残す（会話限りにしない。次回以降も参照できる資産にする）
2. **計画に反映**: そのベストプラクティスを前提に実装計画を立てる。あえて逸脱する場合は理由を明記してユーザーの判断を仰ぐ
3. **確認しながら実装**: 定石どおりに進めつつ、トレードオフ・影響範囲・UX変化がある要所ではユーザーに確認する
4. **段階的に改善**: 一度に全部入れず、スライス単位で検証（build/tsc/実描画）→改善しながら定着させる

## 計画の鬼チェック（敵対的レビュー）

実装前に以下の観点で計画の穴を潰す:

- [ ] **送信/保存失敗時のUX**: 失敗時にどこに留まるか・入力は保持されるか
- [ ] **二重送信ガード** / レート制限時の文言
- [ ] **戻る・再入場での入力保持** / dirty状態の離脱ガード（確認ダイアログ + beforeunload）
- [ ] **モバイル未定義**: Figmaがデスクトップのみの場合、レスポンシブ挙動を計画に明記する
- [ ] **prefers-reduced-motion**: アニメには必ずフォールバックを付ける
- [ ] **データの真実が二重化しないか**: 定数とDBは一方向同期にする
- [ ] **参照整合**: slug→ID解決の防御。解決不能は非表示 + ログ（クラッシュも黙殺もしない）

## スライス分割

大きなタスクは**受け入れ条件付きスライス**に割り、1スライスごとに:

実装 → 静的検証（`npx tsc --noEmit` / `npm run build` / `npm run lint` / `npm test`）→ 受け入れ確認

## 実ブラウザ動作検証を省略しない

**build/tscが通っても「動く」とは言わない。**

- claude-in-chrome で実際にクリックして通す
- コンソール・`.next/dev/logs/next-development.log`・SupabaseログまでE2Eで確認する
- 実例: コメント削除のRLSバグは UPDATE+RETURNING と SELECTポリシーの衝突で、**実際に押すまで発見できなかった**（静的検証は全て通っていた）

## issueのwiki運用

- rebono/issues のMDに **決定事項 / スライス / 進捗ログ / 未決Q** を追記し続ける
- 完了時は `status: review` にし、チェックリストを**「動作確認済み（AI実施）」と「ユーザーの目視が必要」に分けて**簡潔に書く

## 本番デプロイ後のエラー監視（厳守）

**本番（main）にマージ／デプロイした後は、必ず本番のランタイムエラーを確認してから「完了」とする。**

- Vercel MCP の `get_runtime_errors`（直近 3〜6h）で、**402/500/`plan_limit_reached`/新規エラー**が出ていないか確認する
- 自分の変更起因でなくても（例: Sanity API枠超過、認証レート制限、Socketタイムアウト等）、**本番が壊れているサインを見つけたら作業を止めてユーザーに報告**する。「気づかないまま進める」を禁止する
- インフラ・データ取得・キャッシュ・認証・外部サービス連携に触れた変更では特に念入りに見る
- 継続監視が必要なら、Sanity純正の使用量アラート（メール）や定期チェックの仕組み化をユーザーに提案する

## 環境安全

- 本番書き込み（Sanity / Supabase / Stripe）は必ず **dry-run → 内容提示 → ユーザー承認 → 実行**
- 削除は対象一覧を提示してから実行する
- 作業前に**ローカル/本番のどちらに繋がっているか**（`.env.local`）を確認する
