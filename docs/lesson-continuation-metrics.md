# レッスン完了後の学習継続

## イベント配布用の数字（2026年9月24日集計）

対象は、2026年6月上旬〜9月中旬にレッスン内の全記事を完了した、有料登録履歴のあるメンバーです。期間中に複数のレッスンを完了した人は、最初の完了だけを起点にしました。割合は5ポイント単位に丸めています。

| レッスン完了後の行動 | 割合 |
| --- | ---: |
| 24時間以内に別レッスンの記事を完了 | 約55% |
| 24時間後〜7日以内に別レッスンの記事を完了 | 約20% |
| 7日以内に別レッスンの記事完了を確認できない | 約25% |

ここで測っているのは「別レッスンの記事の完了」です。最後の行には、別レッスンを見たり選んだりしたものの、記事を完了していない人も含まれます。数字だけから「次に何を学ぶか迷った」とは判断できません。画面と実際のメンバーの声を合わせて、その可能性を考えるための資料として使ってください。

レッスン別の割合は、この期間では対象者が少ないため配布資料に載せません。検索行動も同じ完了者に結び付けられないため、この表には混ぜません。

## 集計定義と再実行

- 起点: 現在Sanityにあるレッスンの記事IDが、同じメンバーの `article_progress` ですべて `completed` になった時点。時刻は、それらの記事の `completed_at` の最大値。
- 継続: 起点より後、7日以内に、別レッスンの記事の `completed_at` があること。閲覧・動画再生・選択の記録ではない。
- 対象: `user_subscriptions` に `environment=live` かつ有料プラン（`standard` または `feedback`）の登録があり、その作成日時が起点以前の人。`--membership=active` なら集計日時点でも有効な人に限定する。
- 観察期間: 7日率には、集計日より7日以上前の完了だけを使う。30日率も同様に30日以上前の完了だけを使う。
- 単位: `perMemberFirstCompletion` は期間中の最初の完了を1人1回、`perCompletion` は1人が複数レッスンを完了した場合も各完了を数える。配布用の表には前者を使った。

SupabaseとSanityのサーバー用環境変数を設定した環境で、次を実行します。スクリプトは読み取りのみで、個人別の行は保存・出力しません。

```bash
node --env-file=.env.local scripts/analyze-lesson-continuation.mjs \
  --since=2026-06-01 --as-of=2026-09-24 --membership=ever
```

### 解釈上の制約

- `article_progress` は現在の状態です。完了を取り消した履歴や、後から追加・削除された記事を含む過去時点のレッスン構成は再現できません。
- `lesson_progress` の完了は、進捗100%になったときの自動記録ではなく、マイページで完了ボタンを押したときの記録です。スクリプトには比較用として両方の定義を出します。
- 「有料登録履歴あり」は、完了日時にサブスクリプションが有効だったことまでは保証しません。現在有効な人だけに限定すると、離脱した人を落とす偏りがあります。
- 継続の計測は記事完了までです。次のレッスンを探した、閲覧した、動画を開始した、といった行動や迷った理由を知るには、別の計測と聞き取りが必要です。
