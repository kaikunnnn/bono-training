# ペルソナ中心のUIデザイン：レッスントップ MVPリリース計画

- 作成日: 2026-09-16
- 対象レッスン: `scenario-based-design`（ペルソナ中心のUIデザイン）
- デザイン確認ページ: `http://localhost:3001/dev/lesson-top-v8-editorial`
- 本番想定URL: `/lessons/scenario-based-design`
- ステータス: 実装済み・ローカル検証済み（リリース前レビュー待ち）

## 1. このドキュメントの目的

開発用ページで確定したレッスントップのデザインを、ペルソナ中心のUIデザインにだけ適用してMVPリリースするための実装方針を整理する。

レビューでは、次の点を確認してほしい。

1. 対象範囲が限定されているか
2. 既存の記事閲覧・進捗・購読判定を壊さないか
3. 開発用の比較機能やURLが本番へ混入しないか
4. リリース前に解消すべきリスクが残っていないか

## 2. 結論

実装は可能。DB移行やSanityスキーマ変更は不要で、`scenario-based-design` だけを判定するslug分岐をリリースコミットで新設し、対象レッスンのトップだけを差し替えられる。

`origin/main` の `/lessons/[slug]/page.tsx` にはslug分岐がなく、すべてのレッスンが `LessonDetailClient` を表示している。現在のworktreeにある `LessonTopV2Client` への分岐は未コミットの試作であり、本番の既存機能として扱わない。

実装は `origin/main` を取り込んだ最新の基準上で行う。ロールバックは、リリースで追加したslug分岐を外し、すべてのslugを再び `LessonDetailClient` へ渡すことで行う。

### ゲート0：実装前の必須条件

レビュー時点で、このブランチは `origin/main` より107コミット遅れている。実装開始前にmainを取り込み、競合を解消し、取り込み後のコードを基準に設計・ビルド・テスト・ブラウザ確認をすべてやり直す。

実装時は `origin/main` の `816efccb` までfast-forwardし、このゲートを解消した。

107コミットには、少なくとも次の変更が含まれている。

- 本番から `/dev` を遮断するproxyゲート
- 課金・購読周辺の変更
- SEOメタデータの変更
- `/contents` のレガシー記事救済処理

現在変更中の `Layout.tsx`、`sanity.ts`、`globals.css`、`/lessons/[slug]/page.tsx` などは競合する可能性が高い。現在のworktreeをそのままリリース元にしない。

## 3. 対象範囲

### 変更するもの

- `/lessons/scenario-based-design` のレッスントップ
- 対象トップで使用する専用コンポーネントとCSS
- 対象トップで使用する静的画像・SVG
- 対象トップへ渡すデータの整形処理
- 対象トップ内のCTAとカリキュラムリンク
- 対象トップ内のプラン別表示

### 変更しないもの

- その他すべての `/lessons/[slug]`
- `/articles` の記事一覧
- `/contents/[slug]` の教材本文レイアウト
- 記事の動画、本文、ブックマーク、完了ボタン、前後ナビゲーション
- 記事ページの左サイドナビ
- マイページの履歴、ブックマーク、進捗、途中から再開する導線
- グローバルナビゲーション
- Sanityのスキーマ

BONOでは記事一覧が `/articles`、実際の教材閲覧ページが `/contents/[slug]` になっている。レッスントップの「トレーニングをはじめる」とカリキュラム各行は、既存の教材閲覧ページである `/contents/[slug]` へ遷移させる。

## 4. リリース後のルーティング

| URL | リリース後の挙動 |
| --- | --- |
| `/lessons/scenario-based-design` | 今回の確定デザインを表示 |
| `/lessons/{その他のslug}` | 現行の `LessonDetailClient` を表示 |
| `/articles` | 現行の記事一覧を表示 |
| `/contents/{article-slug}` | 現行の教材本文を表示 |
| `/dev/lesson-top-v8-editorial` | 現worktreeのデザイン比較用。MVPリリースコミットには含めない |
| `/dev/persona-editorial/{slug}` | 現worktreeの検証用。MVPリリースコミットには含めない |

記事ページのサイドナビにあるレッスンカードは、既存どおり `/lessons/scenario-based-design` へ戻る。そのため、対象トップを差し替えるだけで往復の導線がつながる。

## 5. 確定デザインの仕様

### ヒーロー

- 左にタイトル、説明、開始CTAを表示
- 右にコースアイコンを表示
- アーチ背景自体にはシャドウを付けない
- コースアイコンは右上・右下を14pxで角丸にする
- コースアイコンのシャドウはデザインシステムへ追加する専用トークンを使う。現在の基準値は `0 1px 24px 2px`、黒8%相当
- アイキャッチ下の区切りはデザインシステム側の波線に戻す
- `FROM USER INSIGHT TO UI EXPERIENCE` は通常のテキスト色にする
- `PERSONA → EXPERIENCE / BONO / DESIGN STUDY` は表示しない

### トレーニング概要

- テキストとスライドを縦に配置
- メディア領域は本文幅の約120%まで広げる
- 「目指す状態」は概要内には置かない

### カリキュラム

- 最初のクエストだけ開いた状態で開始
- 開いている状態はマイナス、閉じている状態はプラスで表現
- 丸ボタンは32 × 32px
- クエストタイトル横に項目数を表示
- 記事のサムネイルを表示
- 記事・動画の種別はアイコンで表示
- 動画だけサムネイル中央に再生アイコンを表示
- 動画時間はSanityに値がある場合だけ表示
- 無料は10pxの緑文字と緑ボーダーで表示
- 有料は鍵アイコンで表示
- 閲覧可能な有料記事はグレーの解錠アイコンで表示
- 右端に遷移を示す矢印を表示
- ホバー時は薄いグレー背景にする
- ホバー時も右端の矢印色は変えない
- 「トレーニングの準備」の種別は「イントロ」にする

### 制作するもの

- AI生成画像は使用しない
- Iconsaxパターンを採用
- `Book1`、`Magicpen`、`Briefcase` のアイコンを使う
- アイコンには開始CTAと同じグラデーションを適用
- アイコン領域は168 × 126pxの4:3
- カード最小高さは304px
- 「社内で使う本シェアサービス」の説明は「解説しながら進めるお題です。初心者におすすめ。」
- 補足は「お題の詳細は『準備』で説明します。」

### 目指す状態

- 「制作するもの」の直後に配置
- 「利用シーン」と同じ左右分割レイアウト
- PCは左40%・右60%
- 01〜04を縦に表示

### 下部セクション

次のセクションは、PCで左40%・右60%に統一する。

- 目指す状態
- 利用シーン
- おすすめな人
- つくった人

モバイルでは縦積みにする。

### セクション共通

- 白い領域へ追加の背景色を敷かない
- セクション間の余白を64px基準で統一
- 区切り線は右カラム全体ではなく、コンテンツ領域の左右端に揃える

### UIアイコン方針とトークン化

`.claude/rules/03-ui-conventions.md` は、IconsaxとLucideの両方を正式な選択肢としている。プロダクト・カテゴリ・ナビゲーションの概念アイコンはIconsaxを第一選択とし、操作系や既存shadcn/ui部品ではLucideを使用する。

今回の制作物カードと鍵表示には、比較検討で採用した次のIconsaxアイコンを使用する。

- `Book1`
- `Magicpen`
- `Briefcase`
- `Lock1`
- `Unlock`

プラス、マイナス、矢印、動画、記事などの操作・状態説明アイコンは、用途と既存コンポーネントとの一貫性を見てIconsaxまたはLucideから選ぶ。同じ役割のアイコンはページ内で統一する。

SVGグラデーションの `#06175a`、`#25408d`、`#e0b0d2` をJSXへ直書きしない。`colors_and_type.css` に次の用途のトークンを追加し、開始CTAとSVGの両方から参照する。

- グラデーション開始色
- グラデーション中間色
- グラデーション終了色
- 開始CTA用グラデーション
- コースアイコン用シャドウ

- クエストID、番号、タイトル
- 記事ID、slug、タイトル、概要
- `articleType`
- サムネイル
- 動画URL、動画時間
- `isPremium`

### 対象レッスン専用設定として管理するもの

- ヒーローコピー

- 制作するもの
- 目指す状態
- 利用シーン
- おすすめな人
- 制作者紹介

MVPではこれらを対象slug専用のTypeScript設定にまとめる。コンポーネント内へ文章を直接散らさない。

### サーバー側で計算するもの

- 記事番号
- サムネイルURL
- 記事が準備中か
- 記事がロックされているか
- ユーザーが全コンテンツを閲覧できるか
- 最初に開始できる記事

クライアントへプラン名や購読レコード自体は渡さず、表示に必要な真偽値だけを渡す。

## 9. 購読プラン別の表示

| 状態 | 無料記事 | 有料記事 |
| --- | --- | --- |
| 未ログイン | 「無料」を表示 | 鍵を表示 |
| 無料会員 | 「無料」を表示 | 鍵を表示 |
| 有効なスタンダード | ラベルを表示しない | グレーの解錠アイコン |
| 有効なフィードバック | ラベルを表示しない | グレーの解錠アイコン |
| 失効済み契約 | 「無料」を表示 | 鍵を表示 |

### リリース前に必ず直す点

現在の `/contents/[slug]` は、記事アクセス判定へ `subscription.planType` を直接渡している。一方、開発中の新トップは `subscription.hasLearningAccess` も確認している。

`getSubscriptionStatus` は `is_active=false` の場合も `planType` をそのまま返すため、失効済み契約のレコードに `planType` が残ると、新トップでは鍵が表示される一方、記事本文は閲覧できる。この不一致はコード上で確定している。

購読状態から有効なプランを求める共通関数を用意し、レッスントップと `/contents/[slug]` の記事アクセス判定の両方で使用する。記事のレイアウトは変更しない。

この修正により、現在は誤って閲覧できている可能性がある失効ユーザーのアクセスが閉じる。ペイウォールの不具合修正として扱い、リリース時の挙動変更として記録する。失効済み契約のテストケースを必須にする。

## 10. 進捗・マイページとの関係

今回のトップ差し替えでは、記事ID、レッスンID、記事URLを変更しない。

そのため、次の既存機能は維持される。

- 記事の閲覧履歴
- 完了記録
- ブックマーク
- マイページの進捗
- マイページから途中の記事へ戻る導線
- 記事ページ内の前後移動

トップの開始CTAは、最初の公開済み記事へ遷移する。途中から再開する機能は、現行どおりマイページ側が担当する。

## 11. 実装手順

1. `origin/main` を取り込み、競合を解消する
2. main取り込み後の状態で既存テストとビルドを通す
3. `scenario-based-design` を対象とするslug定数を新設する
4. 開発版から確定デザインだけを本番用コンポーネントへ抽出する
5. 固定コピーを `persona-lesson-top-config.ts` へ一本化する
6. CSSから比較用・不採用パターンを削除する
7. グラデーション色とシャドウをデザイントークン化する
8. `hero-gradient.png` と `persona-icon.jpeg` をWebPまたはAVIFへ圧縮する
9. サーバー側で対象レッスン用の表示データを整形する
10. すべての教材リンクを `/contents/[slug]` に固定する
11. `/lessons/[slug]/page.tsx` に対象slug分岐を新設する
12. 有効プラン判定を共通化し、新トップと記事本文へ適用する
13. 自動テスト、SEO見出し監査、ビルド、実ブラウザ確認を行う
14. 対象ファイルだけを独立したコミットにまとめる

## 12. テスト計画

### 自動テスト

- 対象slugで新トップが表示される
- その他のslugで現行トップが表示される
- 最初の公開済み記事が開始CTAのリンクになる
- 準備中の記事にはリンクが付かない
- 最初のクエストだけが初期状態で開く
- クエストをプラス・マイナスで開閉できる
- 記事リンクがすべて `/contents/` から始まる
- HTMLに `/dev/` が含まれない
- 無料ユーザーの無料・有料表示が正しい
- スタンダード／フィードバックの解錠表示が正しい
- 動画だけ再生アイコンを表示する
- 動画時間がある場合だけ時間を表示する
- 失効済みプランでは有料記事を閲覧できない
- SVGやJSXに新規の生hex/rgbが含まれない

### SEO・見出し監査

`.claude/rules/08-seo-semantics.md` に従い、レンダリング後のHTMLから `h1`〜`h6` を抽出して確認する。

- `h1` がページ内に1つだけある
- セクション見出しが `h2`
- セクション内の項目・カード見出しが `h3`
- `h2` から `h4` のような欠番がない
- 見た目の大きさではなく文書構造に沿った見出しレベルになっている

### 実ブラウザ確認

- PC 1280px
- PC 1440px以上
- タブレット
- モバイル
- 左グローバルナビとの幅・スクロール関係
- サムネイルの欠損時表示
- 長い記事タイトル
- クエストの開閉
- CTAから記事への遷移
- 記事サイドナビからレッスントップへ戻る遷移
- 記事完了後のマイページ反映

### アカウント別確認

- 未ログイン
- 無料会員
- 有効なスタンダード
- 有効なフィードバック
- 失効済みスタンダードまたはフィードバック

## 13. リスク一覧

| リスク | 影響 | 優先度 | 対応 |
| --- | --- | --- | --- |
| dev用URLが本番へ残る | 学習記録が残らない検証ページへ遷移する | 高 | 本番のリンク先を `/contents` に固定し、HTMLを検査 |
| 購読判定がトップと記事で異なる | 鍵表示と実際の閲覧可否が一致しない | 高 | 有効プラン判定を共通化 |
| ブランチがmainより107コミット遅れている | セキュリティ・課金・proxy修正を欠いた状態でリリースする | 高 | 実装前にmainを取り込み、全検証をやり直す |
| 作業ツリーに他の検証変更が多い | 意図しない変更を同時リリースする | 高 | 対象ファイルだけを独立コミットにする |
| devコンポーネントを直接流用する | 比較UIや不要コードが本番へ出る | 中 | 確定版コンポーネントを抽出 |
| JSXにグラデーションの生hexが残る | デザイントークン規約に違反する | 中 | 色を `colors_and_type.css` へ移す |
| 設定ファイルが二重化する | コピーや対象slugがずれる | 中 | `persona-lesson-top-config.ts` に一本化し、V2試作をリリースへ含めない |
| 固定コピーとSanityデータがずれる | タイトル・記事内容との不整合 | 中 | slug専用設定へ集約し、公開前に照合 |
| 準備中判定がタイトル文字列依存 | 表記変更で公開扱いになる | 中 | MVPではテストで固定し、将来は公開状態フィールド化 |
| `hero-gradient.png` が約1.6MB、`persona-icon.jpeg` が約412KB | 初回表示が遅くなる | 中 | 両方をWebP/AVIFへ変換して比較 |
| サムネイルが参照形式だけで入る | 一覧で画像が出ない | 中 | サーバーで `urlFor` を使ってURL化 |
| 見出し階層が不正 | SEO・アクセシビリティが低下する | 中 | レンダリングHTMLでh1〜h6を監査 |
| 固定の文章量を超える | レイアウトが崩れる | 低 | 長文・欠損データの表示確認 |

## 14. 実装時の作業ツリーについて

実装前に既存変更をstashと `/tmp` のバックアップへ退避し、`origin/main` の `816efccb` までfast-forwardした。その後、最新main上で本番対象ファイルだけを実装・検証した。dev検証ページとV2試作はMVP実装へ含めていない。

MVPリリース用コミットへ含めるファイルは、原則として次に限定する。

- 対象slugの本番分岐
- 本番用レッスントップコンポーネント
- 本番用CSS
- 対象slug専用設定
- 必要な画像とSVG
- 対応するテスト
- 購読判定を共通化する場合は、その小さな修正

記事レイアウト、dev比較ページ、`LessonTopV2Client`、`lesson-v2-config.ts`、他のデザイン検証はMVPリリースコミットへ含めない。

## 15. ロールバック方法

問題が発生した場合は、リリースで追加した `scenario-based-design` 分岐を削除し、対象レッスンも含めて既存の `LessonDetailClient` を表示する状態へ戻す。

記事URL、記事ID、Sanityスキーマを変更しないため、ロールバック時にも学習履歴やブックマークは失われない。
