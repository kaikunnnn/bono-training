# 2026年9月のサイト移行後: /guide の重複とインデックス登録

## 対応方針

- 同じ本文を持つ `/guide/{slug}` と `/contents/{slug}` は `/guide` を検索上の正規 URL にする。
- `/contents` はレッスンの動画、進捗、前後移動に使うため残す。本文を照合できた6組のみ canonical を変更する。
- サイトマップには正規 URL の `/guide` のみ掲載し、該当する `/contents` は除外する。
- 重複する `/contents` の Article 構造化データは出さず、正規の `/guide` 側だけで出す。
- 有料の `/contents` はサイトマップから外し、ページには `noindex,follow` を付ける。無料の非重複記事は自己 canonical のまま残す。
- 既存の5件の `/contents` → `/guide` 恒久リダイレクトは維持する。本文が異なる同名ページは対象にしない。

対象6件: `portfolio-01`、`rdm-howtostart-roadmap`、`beginner-to-uiux-designer-examples`、`become-uiux-designer-beginner-guide`、`how-to-find-jobs-for-beginner-designers`、`uiux-interview-tips-and-checkpoints`。

| Google検索クリック | 188 | 161 |
| 表示回数 | 6,244 | 4,581 |

サイトマップ `/sitemap.xml` は9/23に正常読み込み。9/21更新の「送信済みページ」レポートでは192件中162件登録、30件未登録。そのうち24件が「検出 - インデックス未登録」（未クロール）。確認できた `/guide` の例は次の4件。

- `/guide/beginner-to-uiux-designer-examples`
- `/guide/portfolio-01`
- `/guide/rdm-howtostart-roadmap`
- `/guide/uiux-interview-tips-and-checkpoints`

この4件は「検出 - インデックス未登録」の**例**であり、24件すべてが `/guide` という意味ではない。

9/24のデプロイ後、公開サイトマップは585件（うち `/contents` 493件）に増えた。旧実装はサイトマップ生成時に公開サイト自身のサイトマップを読み、掲載スラッグを除外していたため、生成回ごとに対象が変わる。追加修正で自己参照を外し、無料の非重複記事だけを一定の規則で載せる。GSCの192件は9/21時点の読み込み結果であり、585件をGoogleが送信済みとして処理した数ではない。

追加修正の本番ビルドをローカル起動した結果は332件（`/contents` 240件）で、連続2回の取得で一致した。公開サイトでも同じ332件（`/contents` 240件）を確認した。記事の増減があれば、その差分はCMSの変更履歴と照合する。

## 9/24の追加調査と修正

- 公開中の `/guide` 15件はすべてHTTP 200で、自己 canonical があり、`/guide` 一覧からリンクされていた。`robots.txt` によるブロックもない。サイト側で確認できる範囲では、4件が「検出 - インデックス未登録」となる直接の障害は見つからなかった。
- 15件中4件はCMSの説明文が空で、検索向けの `<meta name="description">` がなかった。本文に沿う説明文を4件に設定し、CMS側で説明文が入ればそちらを優先する。
- サイトマップは従来、掲載URLすべてに生成時刻を `<lastmod>` として付けていた。実際の更新日が取得できる `/guide` にCMSの `_updatedAt` を使い、取得できないURLは更新日を省略する。有料ガイドは有料記事と同様にサイトマップから除き、`noindex,follow` とする。
- クリック減少が目立った `/contents/designer-uiux-mac-2025` はHTTP 200、自己 canonical、タイトルと説明文も確認できた。9/8–14の9クリックから9/15–21の1クリックへの変化は、ページのHTTP/metadataだけでは説明できない。検索クエリ・掲載順位の比較が必要。

## 次回以降の確認

最初の再確認を9/28に行い、その後はデプロイから約1週・2週・4週を目安に、Search Console のレポート更新日を添えて同じ条件で記録する。公開・デプロイ前後のデータを混同しない。

1. 公開サイトマップの総件数と `/contents` 件数を記録する。CMSで記事の公開状態が変わらない限り、件数が大きく揺れないことを確認する。
2. 「インデックス作成 → ページ」で**送信済みページ**に絞り、登録済み・未登録・「検出 - インデックス未登録」の件数を記録する。サイトマップの件数が変わった直後は旧集計と単純比較しない。
3. 上記4件と今回の正規化対象の `/guide` 6件をURL検査し、「Google が選択した正規URL」「最終クロール日」「登録状態」を記録する。自サイト指定の canonical だけで成功と判定しない。
4. 「検索パフォーマンス」で各7日間を比較する。サイト全体に加え、ページを `/guide/` と `/contents/` で絞り、クリック・表示回数・CTRを記録する。旧URLから新URLへの表示移動も見る。

5. デプロイ後に、6件の `/contents` がHTTP 200を保ち、canonical が対応する `/guide`、`/guide` 側は自己 canonical、サイトマップに旧URLがないことを確認する。有料記事がサイトマップに載らず、`noindex` を返すことも確認する。
